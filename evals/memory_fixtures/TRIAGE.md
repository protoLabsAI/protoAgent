The probe calls `evals.memory_retrieval.topk(case["question"], store,
ProjectionOptions())` on fresh stores from `load_fixture_store(path, None)`;
changed-fact stores use `seed_changed_fact(case, user_130_path, None)`, matching
`evaluate`'s first-PV4-user distractor selection. This exercises the real runtime
FTS fallback, without fake retrieval vectors, model answers, or rewritten queries.
Defaults are top_k=5, inject_min_trust=1, no namespace filter. Every listed returned
row is live. Scores are SQLite FTS5 BM25 (lower is better), before trust ordering;
rank is the actual returned order. No cosine score exists in this probe.
[Machine-readable receipts](TRIAGE-evidence.json) retain full retrieved content,
checked row contents, supersession links, unrounded BM25 scores and scorer controls.

PV4 scoring chooses the nonempty candidate nearest the generated answer by cosine,
then tests equality with the frozen reference. For each case, an offline control
returns that exact reference with distinct one-hot candidate vectors: all 23 pass.
This checks loading, candidate filtering and equality, **not** Qwen's semantic
ranking of a paraphrase or Haiku's ability to infer an answer. Those model errors
remain real findings, not permission to relax the scorer. Changed-fact controls use
the actual new and old strings: new-only passes, old-only and mixed fail in all
three cases. Seeding produces row 617 superseded by live row 618 in each fresh copy.

Labels identify the supported failure category, with fixture gaps taking precedence
when a distinguishing fact is lost or absent. A retrieval miss includes model
inference failure; live supporting facts need not literally spell out a hypothetical
answer. In the absence of historical responses, the table cannot distinguish those
two causes or definitively rule out a Qwen-specific grading defect. A passing fake
control alone is not evidence that the historical answer was wrong.
