- **A plugin you placed by hand stays visible, and removable, after protoAgent starts shipping it (#3455).** A copy in your plugins dir with no `plugins.lock` entry — dropped in, or symlinked to a dev checkout — used to stop being what runs, silently, the moment a newer bundled copy of the same plugin arrived, and `plugin uninstall` then refused it as a built-in. It is now reported in its own words (naming the path), flagged in the Plugins list, and removable; a symlinked checkout is unlinked, never followed. The same report now also shows for a bundled plugin that is merely off by default (an explicit `plugins.disabled` still silences it). A relative `plugins.dir` is refused with a warning instead of resolving differently in each process, and the managed-MCP subprocess now finds plugins under a configured `plugins.dir`.
