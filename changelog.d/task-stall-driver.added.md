- **Task stall detection groundwork: a shared "is this task driven?" test (ADR 0129 D9).** `tasks.stall` adds `is_driven` and `find_stalled` — a point-in-time check that an `in_progress` task has something behind it (an unresolved link, a pending schedule or `wait`, an active watch, a running delegation or background job, or a live turn in its session) and, if not and it has gone 30 minutes without an update, flags it as stalled. A source that can't be read counts as driven, so a transient read failure never nudges a task on missing evidence. The task store gains a non-destructive `stall_nudges` counter that `record_stall_nudge` bumps without touching `updated_at` and any real `update` resets. The 5-minute sweep that acts on this lands in a follow-up slice.
