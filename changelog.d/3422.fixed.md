- **A fail-closed TLS assertion now accepts a handshake timeout (#3422).**
  `tests/test_os_trust_store.py` reddened the Windows shard on PRs that never touch it —
  #3395 changes `console_handlers.py` and `types.ts` and nothing else, and still failed on
  `httpx.ConnectTimeout: _ssl.c:993: The handshake operation timed out`. Four sites asserted
  `httpx.ConnectError` specifically with a 5s client timeout, but a handshake against a cert
  the trust store rejects can exceed that on the Windows runner, and httpx raises
  `ConnectTimeout` instead. The security property held the whole time; the assertion was
  narrower than the property it was checking. Deliberately not relaxed to the tidier-looking
  `httpx.TransportError`, which also covers `ReadTimeout` — that happens *after* a successful
  handshake, so a real `verify=False` regression could satisfy it. Both accepted types are
  connection-phase failures a verified connection cannot produce; a regression returns 200
  and still fails.
