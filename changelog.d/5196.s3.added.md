- **Console live-sync client: cursor resume + entity refetch (#5196, ADR 0130 S3).** The operator console now follows the server's change feed instead of guessing per device. The one `EventSource` persists its last bus seq per agent — a synchronous `sessionStorage` mirror plus a durable IndexedDB copy (`lib/syncCursor.ts`, a new `cursors` store on the transcript DB) — and resumes with `Last-Event-ID`/`?since=` on reconnect, when the tab regains focus or visibility, and on wake from sleep, so a slept laptop or a reopened pane replays from its cursor rather than refetching blind. A `session.changed` or `turn.*` frame routes to an entity refetch (the session index and any open session the server has moved past, deduped against the local transcript so no row doubles); `resync_required` forces a full refetch of the session list and every open session's turns; and on return the console compares each open session's `last_change_seq` with the server's as a backstop for anything the feed missed while the stream was down. This flips S0 case 1 (a send in one client appears in the other within 2s, no reload) to green.
