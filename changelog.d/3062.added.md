- **A chat is a room you can see the members of (#3049).**
  `@`-ing a delegate now *pulls them into the room*: the session keeps a participant list,
  a quiet roster strip above the composer shows who is in it, and each chip removes its
  participant in one click. Emptying the roster turns the tab back into an ordinary chat
  rather than leaving an empty-roster special case behind.
  Room members sort to the top of the `@` popover, in the order the operator built the
  room. **Ordering, not filtering** — `@somebody-else` still routes, because a room's
  membership is a convenience and refusing an address would be a surprise rather than a
  safety property.
  The reuse guard learned about rooms too: asking for a new chat never hands back a room
  (which would silently put the operator in one), and asking for a room never hands back a
  plain blank (which would lose the roster). Membership is compared as a set, so the same
  people in a different order still reuse the same empty room.
  Client-side only, persisted with the rest of the session. Telling the *lead agent* who is
  listening is deliberately not in here — that is tokens on every turn and its own call.
