- **Decisions record lookup by id (#4725).** The fleet-wide `useDecisions()` store now keeps a by-id record cache alongside the pending list, so a chat transcript can read a decision that has since been answered, expired, or withdrawn. A pending refresh merges its rows in and a row that leaves the pending list keeps its last known record; `answer()`/`cancel()` store the row the server returns; a new `loadDecision(id)` fetches a historical id over `GET /api/decisions/{id}` (concurrent callers share one request, a 404 latches as missing so there is no retry loop); and a `decision.changed` event naming a cached id that has left the pending list re-reads it by id so the cache never keeps a stale pending record. A new `useDecision(id)` hook returns `{record, state}` (`loading` | `ready` | `missing`). Settled records never count as pending, never notify, and never appear in the panel. Part of #4725.
