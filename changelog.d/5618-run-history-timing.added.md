- **Run history entries carry start, end, duration and whether the run reported.** Each run from `GET /api/scheduler/jobs/{id}/runs` now also returns `started_at` (when the fire was sent), `ended_at` (when it settled), `duration_s`, and `reported`: `true` when a completed run posted its result card, `false` when it completed with nothing to report (an empty answer, a `NO_UPDATE` reply or a repeat of its last card), `null` when unknown. Existing scheduler databases upgrade in place and their earlier runs read `null` for all four. Refs #5543.
