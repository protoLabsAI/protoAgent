- **A prompt near the context window no longer fails just because of the output reservation (#3502).**
  `model.max_tokens` is a flat reservation, so a prompt within that many tokens of the window was rejected
  outright ("you requested 32768 output tokens and your prompt contains at least 229377 input tokens"),
  even when a smaller output budget would have fit. Subagent lanes, which run no pruning or compaction,
  had no other way out. When the gateway reports the window, each request now asks for the output room
  that fits. That room is sized off the agent's measured tokens per character from its previous call, not
  a chars/4 guess. A request that already fits goes out unchanged, as does any request before the agent's
  first measurement. If less than 8,192 tokens of room would remain, the request is left alone, so the
  existing overflow recovery (force-compact and retry) handles it.
