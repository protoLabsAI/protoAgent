- **Scheduler and now-inbox hardening (#5126).** The scheduler's one-time store init now closes its SQLite connection on every path, so a `DatabaseError` raised mid-init (for example a lock timeout during an `ALTER TABLE`) can no longer leak it; `_acquire_jobs_lock` logs a warning naming the lock path and reports "not acquired" when the lock file cannot be opened (a missing, read-only or permission-denied directory) instead of crashing startup; and a now-inbox watch evicted from the bounded watch table is kept reachable, so a later failed/canceled/rejected turn still restores its item to the pending queue.
