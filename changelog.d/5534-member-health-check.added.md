- **The agent can watch a fleet member's health with no plugin installed.** A built-in `fleet:member_health` check now ships in the same verifier registry plugins contribute to, so `list_verifiers`, the console's check picker and `create_watch` all offer it on a stock install, and a plugin reload keeps it. `create_watch(check="fleet:member_health", check_args={"member": "<id or name>", "state": "down"})` is met when that member is in the requested state (`healthy`, `down` or `wedged`, or a list of them; default `down`); add `on_change` to get a follow-up turn each time the member goes down, wedges or recovers. The check reads the supervisor's health records and keeps them current itself: when no sweep ran in the last 15 seconds it runs the supervisor's own sweep first (new `supervisor.fresh_member_health()`, the same probes and records, no second prober), so the watch works whether or not a health loop is running. A live member that fails `/healthz` on three checks in a row is `wedged`. Changes found by such a sweep are returned by the next `supervisor.health_sweep()` call, so a loop acting on changes still sees each one once. A member with no record (stopped on purpose, not in this fleet, or already down when first checked) is not met in any state. Because the registry is no longer empty without a plugin, the watch tools and `set_goal` are bound whenever watches or goal mode are enabled, where they used to wait for a plugin to contribute a check. A plugin cannot replace the built-in by registering the same name. Refs #5534 (ADR 0135 D8).
