- **Restart recovery fails a private turn closed when it can no longer run on its bound checkpoint.** With `private_steering.enabled` on, a queued private turn is bound at acceptance to the conversation's checkpoint thread. After a restart, recovery used to send it anyway when that checkpoint had been deleted (it ran on a fresh thread) or when the plugin thread-id resolver was unregistered or raising (it ran on the default `a2a:<session>` thread). Recovery now re-resolves the thread from the persisted resolver inputs with the current resolver, treats a resolver error as a failure, and checks the bound checkpoint still exists; on any mismatch the turn is never started, is closed terminal with its private record kept, the runner is released for later turns, and a warning names the session and the reason (never the private text). The first private turn of a brand-new conversation, accepted before any checkpoint existed, is still recovered and run. The live stream runner applies the same thread check and answers "its private input is unavailable" without running the graph.
