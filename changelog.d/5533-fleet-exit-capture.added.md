- **The hub keeps the evidence when a fleet member dies on its own, and tracks each member's health.** A member that crashed used to vanish from `fleet.json` on the next fleet poll, with nothing kept. Now every place that drops a dead member's record first writes an exit record (member id, pid, time, and the last lines of its log, credentials scrubbed) to `fleet-exits.json` beside `fleet.json`; `supervisor.collect_exits()` returns the ones not read yet. A member you stop yourself leaves no exit record. A new `supervisor.health_sweep(failure_threshold)` checks each running local member's `/healthz` and each remote through the existing probes, and returns only the changes: down, wedged (process alive but the health check failed that many times in a row) and recovered. `supervisor.member_health()` reads the current state. Nothing calls the sweep yet: the loop, paging and restart come in later changes. Refs #5533 (ADR 0135 D8).
