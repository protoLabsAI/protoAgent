- **One console sign-in now serves every instance on the machine (#3113, ADR 0097).** A ChatGPT or
  Claude login belongs to the person at the machine, not to one agent instance, but protoAgent kept
  its copy under the instance config dir — so signing in from one console did nothing for the desktop
  app's other servers, the dev sandbox, or any other instance. Each of those fell back to importing
  the vendor CLI's single-use token and burning it for the rest, which is the cause behind the
  repeated `Codex token refresh failed (HTTP 401)` reports that #3108 and #3112 could only make
  recoverable and honest. The credential store now lives at the box tier, beside `host-config.yaml`
  and the other state every instance already shares, and an instance-local file overrides it when one
  exists. Existence is the whole switch, so this is a no-op upgrade: an instance that already has its
  own credential keeps using it, only instances that never had one start sharing, and writes go back
  to whichever store was read — a deliberately separate account never migrates to the shared one on
  its own. Claude follows the same rule, so its sign-in is console-only too.
  Sharing one file across processes needs more than the in-process lock that was there: a best-effort
  cross-process file lock now wraps the refresh window, and because correctness must not depend on a
  lock, a refusal that slips through re-reads the store and adopts whatever the winner wrote — with a
  shared store a losing process's 401 is usually "someone else just refreshed", not "the login is
  dead". A filesystem that cannot lock degrades to the previous behaviour instead of failing a turn.
  **Behaviour change:** disconnecting a shared login disconnects it for every instance on the machine.
  That is what "disconnect my ChatGPT account" should mean, but it is not what a per-instance mental
  model expects, so the disconnect result now says which scope it acted on.
