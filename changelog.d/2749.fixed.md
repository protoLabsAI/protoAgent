- **A `wait()` scheduled from within a fired wait's own turn no longer silently vanishes
  (#2749).** The scheduler settles a fired one-shot by deleting its row — but `_fire` blocks
  for the entire agent turn, and a turn that calls `wait()` again re-creates the same stable
  `wait:<thread>` job id mid-flight (the wait tool's cancel+re-add supersede). The post-fire
  cleanup matched by id alone, so it deleted the *freshly re-scheduled* wait: the agent
  believed a wake was pending and nothing ever fired. The delete now also matches the fired
  row's `created_at` (stamped at `add_job` time, so it doubles as a generation marker — no
  schema migration): a mid-fire supersede makes it match zero rows, the new wait survives to
  fire at its own time, and the supersede is logged.
