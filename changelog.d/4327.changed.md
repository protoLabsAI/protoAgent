- **Delegation fails fast when a prompt names tools the subagent won't have (#4327).** Before a `task`/`task_batch` delegation starts, the prompt is scanned for tool names that are bound to the lead but not to the chosen subagent (whole-identifier match, so ordinary prose — including the plain word "task" — never trips it). If any are found, the delegation is not dispatched: the lead gets an immediate `Not dispatched: …` result naming the missing tools and the subagent's actual toolset, instead of the subagent running to completion and coming back "blocked". A `run_in_background` delegation is checked against the full toolset it will actually run with (detached jobs run the lead graph fenced by their allowlist), so one is never refused for a tool it would in fact hold. In `task_batch` only the offending item fails inline; its siblings still run. What a subagent inherits is unchanged.
