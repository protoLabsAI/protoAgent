- **execute_code can keep state across a session's runs (experimental).** With the new `execute_code.session_state` flag on (default off), the first `execute_code` call in a session starts a long-lived Python kernel keyed by that session, and later calls run in its globals — so variables, imports and functions carry over, and the model can fetch a large tool result once and filter it again without re-fetching or printing it into context. State is lost when a call times out (which reports `kernel restarted: earlier variables are gone`) or the kernel restarts, and never survives a server restart; a call can pass `fresh=true` to start from a clean slate. With the flag off, nothing changes — every call still runs in a fresh subprocess. ADR 0134 (D1 and the D2 timeout rule).
