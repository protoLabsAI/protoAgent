- **Memory and knowledge get separate projection budgets and labelled sections (#4630).** ADR 0125 P2-F: the per-turn auto-injected layer is split into labelled sections — "Always-on memory" (`MemoryStore.always_on`), "Relevant memory" (top-k `delivery="retrieved"` matches from `MemoryStore.search` — `on_demand` memories stay reachable only through an explicit `memory_search` call and never auto-inject), "Relevant knowledge" (top-k from `KnowledgeStore.search`, each hit cited `[collection · source]`), then the prior-session digest — all inside the one `<injected_memory>` envelope. The memory and knowledge layers each get their OWN char slice of the projection budget (default 40% memory / 60% knowledge), carved deterministically and never shared: a 1 200-chunk knowledge collection can no longer push always-on or relevant memory out of the turn, and a flood of memories can no longer starve the knowledge section. Incognito, the trust-tier floor and namespace scope gate both layers through the same ladder, and each injection-log row (ADR 0069 D6) now carries a `layers` view tagging its injected ids as memory (always-on + recalled) or knowledge.
