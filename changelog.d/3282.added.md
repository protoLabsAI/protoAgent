- **Plugins can now contribute command-palette entries declaratively with a `commands:` manifest block (#3282).**
  Each entry is data, never imported code: a `navigate`/`open_view` action opens one of the plugin's own views (optionally
  morphing it inline in the palette), `tool` calls a route under the plugin's own /api/plugins/<id>/ namespace, `emit`
  publishes on the event bus, and a `provider` turns the entry into a live search. Because the console compiles those
  actions into authenticated calls that carry the operator bearer, the manifest parser drops — rather than keeps with a
  warning, the way it treats a bad view path — any route that leaves the plugin's namespace, any event topic in another
  plugin's namespace, and any action pointing at a view or command the manifest never declared. Entries surface only for
  ENABLED plugins. Alongside it, `views[].palette` is finally validated: `palette: true` used to be dropped silently by
  the console, and now warns.
