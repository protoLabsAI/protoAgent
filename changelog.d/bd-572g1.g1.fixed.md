- **ACP coders no longer end a turn "waiting" on a backgrounded command (bd-572g1).** When Claude Code moves a long command to the background ("Command running in background with ID: …") and ends its turn with a waiting note, the ACP client now re-prompts the same session (up to 3 times, inside the turn's existing timeout) telling the agent to wait on the command itself and answer — over ACP no notification ever wakes it, so the old turn-end was taken as the final answer. Only the follow-up's text becomes the reply; if the command still isn't resolved, the turn carries a `background_pending` stop marker (booked as an unfinished, retry-worthy run, and spelled out on delegate replies) instead of a plausible "waiting…" answer. Agents that never produce the notice are unaffected.
