**A server-fired turn that fails now says so in chat.** Scheduled fires, watch reactions and background push-resumes never stream to the browser, so the `chat.resumed` push is the operator's only live view of them — and it carried no terminal state. A crashed turn arrived as an ordinary answer that trailed off mid-sentence, and one that crashed before saying anything was dropped entirely, leaving no trace in the UI. The push now carries `state` + `error`, and a failed turn renders as a failure with the reason the task already recorded.
