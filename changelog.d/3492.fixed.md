- **A new fleet member never takes a port another instance on the machine records (#3492).** The workspace port allocator skipped only its own instance's members, the hub's port and ports bound right now, so a stopped member of another instance (the desktop app's, a scoped `dev` instance) read as free and the two collided with `EADDRINUSE` once both started. It now also skips every port another instance records in its members' `workspace.yaml` — across this process's box root, the plain data home and the desktop app's config dir — and it chooses and records the port under one lock that every up-to-date instance on the machine shares, so two instances creating members at the same moment cannot both take a port. Existing collisions are not renumbered.
