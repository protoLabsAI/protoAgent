- **An enabled plugin whose Python packages aren't installed now says so, instead of failing at first use (#3450).**
  A plugin's declared `requires_pip` is installed explicitly, never by `install`. A plugin that
  imports its libraries lazily (inside `execute_code`, say) loads fine without them, so the first
  symptom was an ImportError mid-task, with nothing naming the plugin or the fix. The loader now
  reports unsatisfied deps as a setup gap. The banner names the plugin, lists the packages, and
  gives the one command that fixes it, and it clears on the next reload once they arrive. Both
  tiers are covered, and a missing optional package reads as "parts of it don't work" rather than
  "can't run". The setup wizard's post-install dependency report now also lists **bundled**
  plugins, which it couldn't see before. A fresh **server** running the Cowork pack needed both:
  its whole document stack is the optional tier, and four of its five libraries can be missing
  there, while the desktop app has them all frozen in.
