- **`execute_code` audit rows now name the script behind each bridged call.** Every `ptc:` tool-call row from a one-shot `execute_code` run carries the owning call's model tool-call id (`parent_call_id`) and the script's `script_sha256`, so two runs in one session are no longer indistinguishable, and a new `ptc:script` row keeps the full script (not clipped at 500 chars, capped at 64 KB with `code_truncated`) so a `ptc:` row is never an orphan and a long script is never cut off. `AuditLogger.log` gained an optional `extra` for merging keys into a row verbatim. The one-shot path never passes the graph audit middleware, so it now runs each bridged call's args/result and the kept script through the same `redact()` the model-path rows use — a credential in a script or handed to a bridged tool is no longer persisted in plaintext. The session-kernel path is unchanged (a follow-up card).
