- **The building-plugins skill now documents where a plugin's own files go (#4808).** It spells out that `sdk.plugin_store(plugin_id=registry.plugin_id)` resolves to `<instance root>/<plugin_id>[/<subdir>]`, so plugins stop hand-rolling paths; that an id naming a core store (`memory`, `knowledge`, `media`, …) is rejected at load; and that under the host-free testkit the call returns a per-test temp dir, so a tool that writes under its store needs no fallback.
