- **A managing agent can now diagnose a fleet member's logs and A2A tasks in-band (#3170).**
  A new guarded, read-only `fleet_diagnostics` tool lets an explicitly authorized agent read a
  registered member's bounded log tail (`what="logs"`, caller-bounded `lines`, 1..1000) or one
  exact A2A task by id (`what="task"`, `task_id`) — reusing the member diagnostics API from
  #3168 through the existing `/agents/{slug}/api/diagnostics/*` hub proxy rather than opening a
  new path to the member.

  The trust boundary is ADR 0071. Model exposure is **off by default**: the tool binds only when
  `fleet.diagnostics.enabled` is set, so an ordinary agent never sees it. The target is resolved
  **exclusively through the fleet roster** (local workspaces + registered remote members) — the
  model names a member, never a host or URL, so an unknown/unregistered member is refused and
  there is no alternate-address escape hatch. The tool is **read-only**: its only action is a
  `GET` to the diagnostics endpoints — it cannot start a member, resume or answer a task/HITL
  prompt, mutate checkpoints, or change configuration.

  Output is compact and bounded, preserves the server's `truncated`/`malformed`/`note` signals,
  and is passed through the shared credential redactor before it returns. A stopped, unreachable,
  slow, unauthorized, or task-less member becomes a compact `{"ok": false, "error": ...}` object
  instead of an uncaught error. The tool is deliberately **not** added to the operator-MCP
  read-only profile in this slice — that remains a separate security review.
