- **Guarded read-only fleet diagnostics tool — inspect a member's logs or one task, safely (#3170).**
  A new `fleet_diagnostics` agent tool lets an *explicitly authorized* managing agent read a
  registered fleet member's bounded log snapshot or one exact A2A task by id. It resolves the
  member EXCLUSIVELY through the configured fleet roster (host + local workspaces + registered
  remotes) — an unknown/unregistered name is refused, and the tool never constructs an alternate
  host/URL path — and reaches it only through the existing operator-authenticated
  `/agents/<slug>/api/diagnostics/*` API from #3168 (bounded, redacted, read-only), authenticating
  with the loopback fleet service token. Output is compact and structured, caps the returned lines
  to a caller-bounded selector, preserves the server's truncation/malformed signals, and is passed
  through the credential redactor at the tool boundary. Model exposure is default-OFF and explicit:
  the tool binds only when `fleet.diagnostics.enabled` is set (ADR 0071 trust boundary). Every
  failure — an unreachable/stopped member, a timeout, an unauthorized response, a missing task —
  returns an actionable body rather than an uncaught error. It is strictly read-only: it cannot
  start a member, resume/answer a task or human prompt, mutate a checkpoint, or change config. It
  is deliberately kept out of both curated operator-MCP profiles (read-only and full/`*`) — cross-member
  diagnostics over a foreign MCP client remains a separate security review.
