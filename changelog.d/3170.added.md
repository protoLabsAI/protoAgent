- **A managing agent can now read a fleet member's diagnostics — guarded, roster-only, read-only (#3170).**
  A new `fleet_diagnostics` tool lets an explicitly authorized agent inspect a REGISTERED
  member's bounded log snapshot (`kind="logs"`, a caller-bounded `lines` selector) or one exact
  A2A task (`kind="task"`, `task_id`) by reusing that member's own operator-authenticated
  `/api/diagnostics` endpoints (#3168) — no task/log read is duplicated. The member is resolved
  EXCLUSIVELY through the configured fleet roster: a local peer is reached on its loopback port
  with the fleet service token (ADR 0089), a registered remote at its URL with its stored bearer.
  The model never supplies a host or URL, and the task id is url-quoted to a single path segment,
  so there is no alternate path to a member and no way to escape `/api/diagnostics/`.

  Model exposure is **default off** and the operator's explicit choice: the tool binds only when
  `fleet.diagnostics.enabled` is set (ADR 0071), so an ordinary agent turn never sees it and the
  default fleet is not widened. It is read-only — it cannot start a member, resume or answer a
  task/HITL prompt, mutate a checkpoint, or change config. Output stays compact: the tool
  re-redacts known secret forms and re-bounds the response at its own boundary while preserving
  the member's own `truncated`/`malformed` signals, and every failure — unknown or stopped
  member, unreachable, timeout, unauthorized, missing task — comes back as a compact structured
  answer rather than an uncaught error.

  Deliberately out of scope this slice: exposing the tool over the operator MCP (read-only or
  full profile). It is excluded from the MCP wildcard pending its own security review.
