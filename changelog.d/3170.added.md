- **Guarded read-only fleet diagnostics tool — a managing agent can inspect a member's logs
  or one A2A task (#3170).** With the operator's explicit opt-in
  (`tools.fleet_diagnostics_enabled`, **default off**), the lead agent gets a
  `fleet_diagnostics` tool that retrieves, for one registered fleet member you name, either a
  bounded tail of its log ring or one exact A2A task by id — by calling the member's own
  operator-authenticated diagnostics API (#3168) through the hub's canonical
  `/agents/<slug>/api/diagnostics/*` reverse proxy.

  It is bounded by ADR 0071's trust boundary. **Roster-only addressing:** the target is
  resolved through the configured fleet roster and an unregistered name is refused — the tool
  never builds a member host/port/URL of its own (it only ever dials loopback), and the task
  id is percent-encoded, so there is no SSRF or path-traversal surface. **Operator-
  authenticated:** it presents the fleet service token (ADR 0089), which the hub accepts as the
  operator tier and swaps for the member's own credential at the proxy. **Read-only:** GET
  only, against the two diagnostics endpoints — it cannot start a member, resume or answer a
  task or a human-input prompt, mutate a checkpoint, or change configuration. **Bounded +
  redacted:** output is capped (a caller line selector plus a hard ceiling), the member's own
  truncation / malformed / clamp signals are preserved verbatim, and credential redaction runs
  again as defense-in-depth. Every failure — unknown member, unreachable, timeout, unauthorized,
  missing task, malformed body — returns a compact, actionable object rather than an exception.

  Default off keeps ordinary agents untouched. The tool is also deliberately kept **off the
  operator-MCP bus** (it is in neither the `read-only` profile nor the wildcard set); exposing a
  guarded cross-member read to a foreign MCP client is a separate security review.
