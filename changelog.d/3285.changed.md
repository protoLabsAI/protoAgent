- **The Settings section table moved into an import-light leaf module, so deep-linking a
  settings section no longer drags the entire settings UI along (#3285).** The ids, labels,
  icon names, flag/`hostOnly` gates and group order now live in
  `apps/web/src/settings/sections.ts`; `SettingsSurface.tsx` keeps the panels and maps each
  icon name to a statically imported component. Importing anything at all from
  `SettingsSurface` pulled in ~90 modules and ~800 KB of panel source — every settings panel
  plus 26 lucide icons — which is what the ⌘K palette and the desktop Launcher window would
  have paid just to name a section; the leaf costs 2 modules and ~14 KB, and a test pins it
  that way, since CI has no bundle-size gate that would notice the regression. Nothing renders
  differently: no section was added, removed, renamed, reordered or re-gated, and the surface's
  id→panel and name→icon maps are exhaustive over the table, so a section with no panel or an
  unmapped glyph fails the build instead of blanking a pane. Telemetry's glyph is spelled with
  lucide's canonical `ChartColumn` rather than the deprecated `BarChart3` alias (the same
  component, so the rail is unchanged): the alias survives as a top-level export but was dropped
  from lucide's `icons` map, which is what the lazy resolver a name-only consumer uses looks in,
  so it would have rendered a fallback box in ⌘K while looking correct everywhere else.
