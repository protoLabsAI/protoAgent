- **Notices now reach enrolled devices by Web Push, with no chat plugin installed.** At startup the hub registers Web Push as one more adapter behind the existing notice seam (`notify_chat_surfaces`), so there is still a single sender of notices. A notice is written to the bounded delivery ledger and the call returns at once; one maintenance loop sends it, picks up due retries, and after a restart sends what was still pending and drops what has expired. A push service that fails or times out cannot raise into the code that raised the notice or hold up another adapter. There is no setting: a device that enrolled for push is the opt-in, and with none enrolled nothing is sent. A fleet workspace member registers nothing; the hub owns the operator's devices (ADR 0135 W2). Refs #5539.
