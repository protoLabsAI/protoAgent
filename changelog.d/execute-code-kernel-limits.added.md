- **Session kernels stay bounded and tear down with the chat.** With `execute_code.session_state` on, session kernels are now kept within two new, configurable limits so an idle or forgotten chat never leaves a long-lived Python process behind: a kernel left unused for `execute_code.kernel_idle_ttl` seconds (default 600) is stopped and its state discarded, and starting a kernel past `execute_code.max_kernels` (default 4) first stops the least-recently-used one. A session's kernel is also stopped the moment its chat is deleted or cleared, or its tab closes; a chat still in active use keeps its kernel and its state. Unloading, reloading or shutting down the plugin stops every kernel. ADR 0134 (D2).
